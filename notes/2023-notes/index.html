install curl with http3 on mac

# Clean up any old version of curl you may have already tried to install
brew remove -f curl

# Download the curl ruby install script provided by cloudflare
wget https://raw.githubusercontent.com/cloudflare/homebrew-cloudflare/master/curl.rb

# Install curl via that script from the latest git repos
brew install --HEAD -s curl.rb

# Tell your cli to use the curl version just installed (if you're using zsh, othwerise you might need `~/.bashrc`)
echo 'export PATH="/usr/local/opt/curl/bin:$PATH"' >> ~/.zshrc

# Reload your config
source ~/.zshrc

# Double check it's using the right curl
which curl # Should output "/usr/local/opt/curl/bin/curl"

# Double check http3
$ curl --version | grep HTTP3

php - setlocale

  • 起因：用 php 的 pathinfo 或者 basename 截取文件名，某些情况下中文可能会出现问题
  • 解决方案：官方文档也写了，这个函数跟本地语言设置有关系
  • https://www.php.net/manual/en/function.pathinfo.php

Caution pathinfo() is locale aware, so for it to parse a path containing multibyte characters correctly, the matching locale must be set using the setlocale() function.

问题是，如果调用 setlocale 设置的话，参数应该怎么传呢？

从 https://www.php.net/manual/en/function.setlocale.php#90919 这里看，其实要先看系统支持哪些

比如我打包的镜像里是这样查的

root@efe5cf2582e0:/webroot/ewiki# locale -a
C
C.UTF-8
POSIX

root@efe5cf2582e0:/webroot/ewiki# ls /usr/lib/locale
C.UTF-8

所以用法就是

setlocale(LC_ALL, 'C.UTF-8');

当然，这里有一个问题，如果在代码里设置了， 那换一个环境，他可能就不行了，所以最好是通过环境变量来设置，代码里不要设置了。

  php:
    image: harbor.baijiayun.com/bdata/ewiki:v1.0.1
    volumes:
      - .:/webroot/ewiki
      - wiki-repo:/webroot/ewiki/wiki-doc
    networks:
      - ewiki
    container_name: ewiki.php
    environment:
      LC_ALL: C.UTF-8
  • https://stackoverflow.com/questions/4451664/make-php-pathinfo-return-the-correct-filename-if-the-filename-is-utf-8

设置 gitlab runner 运行时的 serviceAccount

怎样指定 gitlab runner 运行时 pod 中的 serviceAccount 呢？

根据官方文档，可以在 .gitlab-ci.yml 中设置

variables:
  KUBERNETES_SERVICE_ACCOUNT_OVERWRITE: ci-service-account

但是下面提示需要开启另外一个变量 KUBERNETES_SERVICE_ACCOUNT_OVERWRITE_ALLOWED，他的值是一个正则表达式。

不过这个变量，直接在 .gitlab-ci.yml 中设置是不生效的，需要在 gitlab-runner chart values.yaml 中修改

envVars:
  - name: KUBERNETES_SERVICE_ACCOUNT_OVERWRITE_ALLOWED
    value: ".*"
  • https://docs.gitlab.com/runner/executors/kubernetes.html#configuring-executor-service-account

怎样检测 fpm 运行状态？

php-fpm 对外提供的是 fastcgi 的接口，我们怎样判断这个服务是否正常呢？

我们可以开启 pm.status_path = /status，把 fpm 的状态暴露出来，但他也还是通过 fastcgi 的形式暴露的。

也就是一般前面还需要再配置一个 nginx 转发，把 http 的 /status 请求转到 fastcgi 的 /status。

有没有不依赖 nginx 的方案呢？

可以用 cgi-fcgi 这个命令

cgi-fcgi 这个命令是做什么的呢？他是一个应用程序，可以与一个 fastcgi 程序交互，得到一个 http 的形式的结果

github 上有一个 php-fpm-healthcheck 的项目，就是基于这个命令，做了一些包装。

  • https://manpages.ubuntu.com/manpages/bionic/man1/cgi-fcgi.1.html

  • https://github.com/renatomefi/php-fpm-healthcheck

如下所示，用同一个 volumes

version: '2.2'
services:
  php:
    image: harbor.baijiayun.com/bdata/dashboard-service:latest
    volumes:
      - webroot:/webroot
      - ./storage:/webroot/dashboard-service/storage:rw
      - ./development/env.local:/webroot/dashboard-service/.env
      - ./development/logs:/apps/logs
      # - <path-to-fe-root>:/webroot/public/dashboard-fe

      - dashboard
    container_name: dashboard.php

    image: nginx:latest
    volumes:
      - webroot:/webroot
      - ./development/nginx.conf:/etc/nginx/nginx.conf
      - ./development/logs:/apps/logs
      # - <path-to-fe-root>:/webroot/public/dashboard-fe
    depends_on:
      - db
    networks:
      - dashboard
    ports:
      - 80:80
    container_name: dashboard.nginx

volumes:
  webroot:

oauth2-proxy

看 github 上 keycloak-proxy 停止维护了，说是因为 oauth2-proxy 提供了类似的功能

  • oauth2-proxy 配置
http_address="0.0.0.0:4180"
cookie_secret="OQINaROshtE9TcZkNAm-5Zs2Pv3xaWytBmc5W7sPX7w="
email_domains=["*"]
cookie_secure="false"
upstreams="http://share.test-at.baijiayun.com"
cookie_domains=["share.test-at.baijiayun.com:4180"] # Required so cookie can be read on all subdomains.
whitelist_domains=["share.test-at.baijiayun.com:4180"] # Required to allow redirection back to original requested target.
pass_host_header="false"

# keycloak provider
client_secret="abcd"
client_id="openresty"
redirect_url="http://share.test-at.baijiayun.com:4180"

# in this case oauth2-proxy is going to visit
# http://keycloak.localtest.me:9080/auth/realms/master/.well-known/openid-configuration for configuration
oidc_issuer_url="http://keycloak.test-bdata-k8s.baijiayun.com/realms/bdata"
provider="oidc"
provider_display_name="Keycloak"

  • 注意事项

    • cookie_domain 要设置对
    • redirect_url 是 oauth2-proxy 的地址，需要在 keycloak 上配置白名单
    • keycloak 里用户的邮箱需要是验证通过的，否则这里不让登录（LDAP 的设置里可以标记成默认验证通过）
    • oauth2-proxy 会默认把当前请求的 Host 发给 upstream，可以通过 pass_host_header 来控制

  • 验证：http://share.test-at.baijiayun.com:4180/json.php

  • https://oauth2-proxy.github.io/oauth2-proxy/docs/configuration/oauth_provider/#keycloak-oidc-auth-provider

怎样给 k8s 添加一条 DNS 解析记录？

要点总结：

  • k8s 的 DNS 解析是由一个 CoreDNS 模块完成的
  • CoreDNS 这个服务加载的配置文件，是在 ConfigMap 里，有一个 Corefile
  • 除了这个 CoreDNS 还有一个 NodeLocalDNS 服务，所以还需要改这个 NodeLocalDNS 的配置
  • NodeLocalDNS 的配置文件跟 CoreDNS 类似，也是放在 ConfigMap 中管理的
  • NodeLocalDNS 模块是能 DaemonSet 的形式运行在每个节点上（当然你也可以不启用这个）
  • 改完配置文件要重启
    • CoreDNS 重启方式，先缩减 pod 到 0，再扩回去
    • NodeLocalDNS 重启方式：直接 kill 掉（DaemonSet 会自动启动起来）
  • 验证有没有生效，可以用 dig @<dns-server> host 的方式，指定 DNS 服务器
  • 可以启动一个 dnstools 的容器来验证
    • kubectl run -it --rm --restart=Never --image=infoblox/dnstools:latest dnstools

相关步骤记录在 /BBS/Yili/k8s/add-custom-dns-entries.md
